# Start here

Before doing anything else in this repo — before exploring code, before answering a question, before making a change — read `AI_LOG.md` in full. It's the running history of AI-assisted work on this project: what was changed, why, and what's still known-broken. Working without it risks redoing something already fixed, re-breaking something already fixed, or repeating an option already ruled out.

As the first line of your first response in a new session here, name the date and one-line summary of the most recent `AI_LOG.md` entry. This isn't for the user's benefit so much as a forcing function — if you can't state it, you haven't actually read the file yet, so go read it before responding.

When you finish something worth remembering (a fix, a refactor, a non-obvious decision — not a typo), append a new dated entry to `AI_LOG.md` in the same format as the existing ones: what changed, why, files touched, commit hash if committed. Keep the "Known issues" list at the bottom current — strike through what you fix, add what you find.
